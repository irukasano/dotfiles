## Review

### 2026-10-20 14:55 : awscli タスク追加

- 原因: `Makefile` に AWS CLI の導入タスクが存在しなかった。
- 修正内容: `.PHONY` の単体 `awscli` タスクを追加し、既存の `YUM` 変数で `awscli` パッケージを導入するようにした。`all` / `base` / `tools-all` の依存関係は変更していない。
- 検証結果: `make -n awscli` は `sudo dnf install -y awscli`、`make -n awscli YUM=apt` は `sudo apt install -y awscli` を表示した。`make help` に `awscli` が表示され、`git diff --check` も成功した。実際のパッケージ導入は実行していない。
- Lesson 照合: `codex-lesson check` でベクトル検索が利用可能と確認。最終回答に対する検索上位 5 件の Scope を照合し、今回のパッケージ導入タスクに適用する Rule はなかった。

### 2026-10-20 15:03 : AWS 公式インストーラーへ変更

- ユーザーの修正指摘: AWS CLI はパッケージマネージャで導入するより、AWS 公式ページにある `curl -fsSL https://awscli.amazonaws.com/v2/install.sh | bash` の方が最新ではないか。
- 一次情報: AWS 公式ガイドはインストールスクリプトを推奨し、外部リポジトリのパッケージに最新版が含まれる保証はないと記載している。
- 修正内容: `awscli` タスクをユーザー提示の公式コマンドに置き換えた。現ユーザー向けの AWS CLI v2 導入となり、`YUM` は使用しない。
- 検証結果: `make -n awscli` と `make -n awscli YUM=apt` がどちらも公式コマンドを表示し、`make help` にタスクが表示された。`git diff --check` 成功。実際のインストールは未実行。
- 制限: 公式例どおりのパイプラインでは `curl` の失敗が bash の終了ステータスで隠れる場合がある。既存インストールの更新は AWS 公式ガイドでは `aws update` を案内している。
- Lesson: `CLI 導入方法は公式推奨を確認する` を追加し、ベクトル検索に登録されたことを確認。最終回答の検索上位 5 件を Scope と照合し、適用するのは今回の lesson のみと判断してこの Review と照合した。
